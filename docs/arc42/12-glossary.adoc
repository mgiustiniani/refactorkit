|PatchPlan
|Structured preview/apply or refusal plan for a code modification, including operation, snapshot hash, affected files, workspace edit, diagnostics, warnings, risk, confidence, and evidence. |PlanId
|Opaque identifier generated for a `PatchPlan`. At a protocol boundary it is a revocable session-scoped lookup handle only when the exact surface-admitted payload is retained in that session's pending managed-plan store. It is not approval, authorization, a transaction ID, or possession-based write authority: explicit apply invocation and all `PatchEngine` gates remain mandatory. An internal lexical review plan's random UUID-based ID is not a protocol handle and must never be exposed or aliased to an `operationId`; unknown `PlanId` input remains `INVALID_PARAMS`.

Missing, evicted, discarded, and cleared identities use the surface's existing indistinguishable not-found behavior.

|Transaction-journal Failure
|Exact `TransactionLogException` identity, code, message, and cause produced by journal access. |Core rollback orchestration / journal safety

|Managed Rollback Executor
|Implemented language-neutral core application service that parses one supplied ID, performs one outer full-record lookup, applies caller-selected visibility, runs an optional surface-owned preflight guard, invokes public `PatchEngine.rollback` exactly once, and returns typed outcomes retaining the exact resolved pre-lock record. It owns no rendering, mode policy, refresh/diagnostics/lifecycle, authorization, WAL/recovery replacement, direct write, or rollback algorithm.
|Core Patch and Model Engine C3 component
|Implemented-and-validated REQ-MANAGED-ROLLBACK-EXECUTOR-001/002; `ManagedRollbackExecutor.kt`; inspected CLI/daemon/LSP/MCP adoption; Chapters 4-10; ADRs 0002/0004; LLM Wiki concept `managed-rollback-executor`
