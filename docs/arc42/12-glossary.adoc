= 12. Glossary
:toc:
:sectnums:

Status: implementation-informed, with confirmed target-scoped Maven move-class authority terms integrated from domain research reviewed on 2026-07-29 and descriptor-closed graph/ordinary missing-binary concepts reviewed on 2026-07-30. REQ-JAVA-MAVEN-MOVE-AUTH-001 validates the bounded complete-`AVAILABLE` binding-clean preview/apply/rollback vocabulary. REQ-JAVA-MAVEN-MOVE-AUTH-002 now validates exact dependency-bounded observer, JDT candidate, Java non-code residual, non-Java residual, managed-edit exclusion, apply, and rollback meanings; `007`, `009`, `010`, `011`, and six-case `012` retain their independently bounded missing-binary, scope, pruning, ordinary-absence, and selected-descriptor meanings. Requirements `003`, `004`, and `008` remain absent. Separately, the exact Magrathea request at commit `a48e3c06` remains CLI-qualified only on Linux/JDK 21 after `010`; no integration/native matrix or general support is inferred.

|Term |Definition |Scope |Evidence

|RefactorKit
|Deterministic refactoring and code-intelligence engine for safe, previewable, rollbackable code transformations.
|System
|README, AGENTS

|PatchPlan
|Structured preview/apply plan for a code modification, including operation, snapshot hash, affected files, workspace edit, diagnostics, warnings, risk, confidence, and evidence. Review-only guided manual fallback is deliberately not a `PatchPlan`.
|Core
|`Models.kt`; ADR 0002; `RPK-JAVA-MOVE-005`

|WorkspaceEdit
|Collection of file edits to modify, create, delete, or rename files in a workspace.
|Core
|`Models.kt`

|TextEdit
|A replacement over a source range.
|Core
|`Models.kt`, `TextEdits.kt`

|PatchEngine
|Core service that locks, preflights, journals, stages, durably commits per-path images, recovers interrupted managed writes, and performs conflict-safe or explicitly forced rollback. Multi-path batches are recoverable rather than one filesystem-wide ACID commit.
|Core
|`PatchEngine.kt`, ADR 0002, transactionality audit

|Transaction
|Domain identity and compensation view embedded in the durable journal record. Journal pre/post images and lifecycle—not the `Transaction` object alone—provide recovery and conflict-safe rollback evidence.
|Core
|`Models.kt`, `docs/transactionality-audit.md`

|Compensatable Batch
|Legacy classification for previewed/preflighted sequential writes with post-success compensation only. Current managed paths have advanced to locked, write-ahead-journaled, durably staged recoverable batches.
|Core / integrations
|ADRs 0002 and 0004, transactionality audit

|Transaction Log
|Versioned write-ahead recovery metadata stored under `.refactorkit/transactions`, durably created before mutation and atomically advanced through apply/rollback/recovery states. Schema-v2 SHA-256 integrity, v1-on-update migration, and blocking owner-only corruption quarantine are implemented; full metadata and complete fault evidence remain planned.
|Core / workspace
|`TransactionLog`, transactionality audit

|Saga
|Multi-step workflow that commits steps separately and attempts later compensation. RefactorKit recipes no longer use this boundary; they stage one recipe-wide transaction.
|Recipes
|ADR 0004, transactionality audit `TX-008`

|ProjectSnapshot
|Immutable snapshot of workspace modules and source files with a content hash.
|Core
|`Models.kt`

|LanguageAdapter
|Contract implemented by language-specific adapters for parse, symbols, references, diagnostics, and refactoring application.
|Core / adapters
|`Models.kt`

|Java Language Adapter
|Java-specific implementation providing source scanning, symbols, references, diagnostics, and refactoring planners.
|Java module
|`JavaLanguageAdapter.kt`

|Symbol
|Named code element such as class, interface, enum, record, annotation type, method, field, constructor, package, or unknown.
|Core / Java
|`Models.kt`

|Annotation Type
|Java `@interface` declaration represented as an `ANNOTATION` symbol. RefactorKit indexes its declaration, nesting owner, binding identity, and usages for type-level lookup and existing class-style operations.
|Core / Java
|`Models.kt`, `JavaLanguageAdapter.kt`, `JdtJavaSemanticAnalyzer.kt`, ADR 0008

|Annotation Element
|Zero-parameter member declared inside a Java annotation type, represented by JDT analysis as a signed `METHOD` symbol such as `com.acme.Route#path()`. Read-only queries and clean exact signed rename cover its declaration and binding-matched named usages; implicit values have no element name to edit. Change-signature and default-value editing are outside this support.
|Java
|`JdtJavaSemanticAnalyzer.kt`, `JavaRenameMemberPlannerTest.kt`, ADR 0008

|Reference
|Source location that references a symbol.
|Core / Java
|`Models.kt`

|Diagnostic
|Structured message with severity and optional location/code.
|Core
|`Models.kt`

|Diagnostics Authority
|The right to use a diagnostic result as semantic evidence for a managed operation. Global Java/Maven authority binds a complete available source-set environment, exact workspace/overlay, Build Model/classpath, Java platform signatures, and provider. Bounded `001` validates one complete-`AVAILABLE` row with zero authoritative before, staged, after, and rollback diagnostics. Bounded `002` independently keeps each selected observer in its exact dependency-bounded environment and excludes unrelated source roots while preserving clean before/staged/restored diagnostics. The qualified target-scoped Maven `moveClass` mode still requires complete structural, candidate-total, staged-delta, and freshness proof; `007`, `009`, `010`, `011`, and `012` cover independently bounded missing-binary, scope, pruning, ordinary-absence, and selected-descriptor shapes. Maven build success is supplementary only.
|Core / Java / safety
|ADR 0012; `RPK-JAVA-DIAG-005`; `RPK-JAVA-MOVE-003..004`; REQ-JAVA-MAVEN-MOVE-AUTH-001, `002`, `007`, `009`, `010`, `011`, and `012`

|Binding-clean Semantic Authority
|Operation- and snapshot-scoped proof that one exact non-recovered JDT target binding and every in-scope Java edit site refer to the same symbol, that the complete authority scope is inventoried without concealment by parse/binding failure or truncation, and that staged re-analysis establishes the new identity. It authorizes semantic plan construction, not mutation by itself. Bounded `002` demonstrates that this selects only the target package/import/FQN edits while exact other-symbol and residual lexical evidence remains non-managed.
|Java semantic refactoring
|ADRs 0008 and 0012; `RPK-JAVA-MOVE-003`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-001/002

|Target-scoped Java Semantic Authority
|Fail-closed proof for one Java semantic operation. Full-reactor active-POM authority, descriptor closure over every selected external node, hash-bound selected/pruned edge classifications, ownership, source inventory, platform/provider, and candidate audit/exclusion remain global. Per-missing-binary negative-presence and retained-diagnostic evidence is required only for the before/staged operation authority closure. The exact target is known, every Java candidate that could denote it is classified, retained closure diagnostics are exactly unchanged and positively non-concealing, and staged evidence has no new or changed error or drift. It is narrower than globally complete source-set diagnostics and does not hide `OFFLINE_MISSING`.
|Java semantic refactoring / Maven move class
|Accepted ADR 0012; `RPK-JAVA-MOVE-001..004`; concepts reviewed 2026-07-29 and 2026-07-30; bounded implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-001, `002`, `007`, `009`, `010`, `011`, and `012`; dated Magrathea CLI field evidence after `010`

|Candidate-total Java Inventory
|Independent, bounded, hash-bound lexical inventory of every old-FQN token and matching simple-name token in a type-capable Java position. Each exact range is classified once by JDT as `BOUND_TARGET`, `BOUND_OTHER`, or `UNRESOLVED`; target-relevant or relevance-uncertain unresolved candidates veto authority. Exact bound totals exclude Java grammar-noncode strings and non-Java text, which are separate residual classes. The inventory finds evidence that binding analysis might omit, but never selects an edit. Bounded `002` reports exactly 12 `BOUND_TARGET`, one exact-binding `BOUND_OTHER`, and zero `UNRESOLVED` JDT records.
|Java move-class completeness
|ADR 0012; `RPK-JAVA-MOVE-003`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-002, `007`, `009`, `010`, and `011`; absent REQ-JAVA-MAVEN-MOVE-AUTH-008

|Java Non-code Residual
|An old-FQN lexical occurrence inside a Java source file but outside a type-capable Java grammar position, such as a string literal. It is not a JDT `BOUND_OTHER` candidate and never selects an edit; reporting marks it `JAVA_NON_CODE_RESIDUAL` and `managedEdit=false` for review. Bounded `002` records exactly one such occurrence in `reporting-unrelated/.../ProductReport.java`, outside the observer closure, and preserves the file byte-for-byte.
|Java move-class residual risk
|`JavaMoveClassCandidateReporter`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-002

|Non-Java Residual
|A path containing old-FQN lexical text in a non-Java file. It has no JDT binding classification and never selects an edit; reporting marks the path `NON_JAVA_RESIDUAL` and `managedEdit=false` for review. Bounded `002` reports `NON_JAVA_RESIDUAL=2` for `catalog-acceptance/src/test/resources/features/product-lifecycle.feature` and the fixture-root `README.md`, and preserves both files byte-for-byte.
|Java move-class residual risk
|`JavaMoveClassCandidateReporter`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-002

|Java Target-name Lookup Protection
|Bounded sidecar-free proof that an ordinary absent binary cannot change what a target spelling denotes. Apart from the selected exact source declaration, a `BOUND_TARGET` occurrence is protected only when it is a simple type use with exactly one resolved non-static single-type import of the exact target FQN, or when the occurrence itself uses that exact FQN; JDT must bind the import/use to the selected declaration in before and staged images. Unprotected simple names, relevant type/static wildcard or unresolved-static ambiguity, same-package/inherited/enclosing lookup, recovered/problem evidence, unresolved candidates, or candidate/diagnostic/edit overlap fail this proof.
|Java move-class target non-concealment
|Accepted ADR 0012; `RPK-JAVA-MOVE-003`; concept reviewed 2026-07-29; bounded `009`/`010` evidence applies to an `AVAILABLE` target closure; implemented-and-validated `011` establishes this proof for one ordinary sidecar-free selected-JAR row

|Isolated Unchanged Baseline Diagnostic
|A retained diagnostic whose provider/configuration, code, category, severity, deterministically mapped path/range, and message have exact before/staged multiset identity, plus positive proof that neither the diagnostic nor its missing input can intersect, introduce, shadow, ambiguate, or conceal target lookup. Unchanged counts or source-set co-location are insufficient.
|Diagnostics / target-scoped authority
|Accepted ADR 0012; `RPK-JAVA-MOVE-003..004`; bounded implemented-and-validated `007` for retained diagnostics and `011` for a zero-diagnostic ordinary row; absent Gherkin `008`

|Maven Reactor Classpath and Source-path Completeness
|Layered proof derived from the declared full effective reactor. Every active reactor POM is mandatory, while external dependency closure is descriptor-closed over selected nodes in every main/test projection. Structural completeness also requires graph/variant and reactor edges, source-set ownership, source/materialized-generated-root inventory, platform/provider facts, full-reactor candidate exclusion, and dependency-bounded reverse-observer facts. External classpath availability is separate. Missing-binary evidence covers only the operation authority closure; full graph discovery never grants unrelated siblings visibility.
|Build Model / Java
|ADRs 0010-0012; `RPK-JAVA-MOVE-002`; bounded REQ-JAVA-MAVEN-MOVE-AUTH-001, `002`, `007`, `009`, `010`, `011`, and `012`

|Maven Descriptor-closed Dependency Graph
|Per-consumer-source-set/projection graph whose active reactor POMs all remain mandatory and whose selected external nodes each have complete effective POM, parent, imported-BOM, management, mediation, and relocation inputs. Every outgoing declaration from an active reactor or selected external effective POM is hash-bound and classified as selected or deterministically pruned with exact path/projection provenance. Closure stops below a pruned external edge, not below a selected node.
|Build Model / Maven diagnostics
|Accepted ADR 0012; descriptor-closed graph concept reviewed 2026-07-30; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-010/012

|Selected Descriptor Authority Context
|RefactorKit-captured baseline for one selected external Maven coordinate. It contains unique safe workspace-relative descriptor path/layer/SHA-256 expectations and a SHA-256 parsed descriptor identity. The parsed identity is explicit proof that the selected model, identity, and relocation state were parsed; descriptor bytes alone cannot silently imply “no relocation.” A missing identity or missing, malformed, or drifted expected descriptor fails structurally before binary classification or semantic selection. REQ-JAVA-MAVEN-MOVE-AUTH-012 records workspace, descriptor facts, evidence records, and evidence hashes around each refusal and proves exact equality after evaluation.
|Build Model / Maven move-class authority
|`MavenSelectedDescriptorAuthorityContext`; `MavenSelectedDescriptorExpectation`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-012

|Deterministically Pruned Maven Edge
|An external dependency edge omitted for one path/projection because derived transitive scope is null/outside that projection, `optional=true` applies transitively, or an exact inherited path exclusion matches. It contributes no child node or subtree, so no child version/repository/POM/JAR/network lookup is required on that path when child facts cannot change selection. Another selected path restores the requirements. Type/classifier alone never prune, and ambiguity fails closed. Bounded REQ-JAVA-MAVEN-MOVE-AUTH-010 serializes six such child declarations as 18 deterministic `PRUNED` records across `COMPILE`, `RUNTIME`, and `TEST`, binding path, projection, reason, variant, and pre-lookup boundary.
|Build Model / Maven dependency selection
|Accepted ADR 0012; descriptor-closed graph concept reviewed 2026-07-30; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-010

|Enumerated Offline Leaf Artifact
|A selected missing non-reactor binary whose operation evidence is bounded to affected closure source sets. Implemented synthetic REQ-JAVA-MAVEN-MOVE-AUTH-007 records a pre-removal expected hash and provided-type manifest plus negative presence. Implemented ordinary REQ-JAVA-MAVEN-MOVE-AUTH-011 instead uses RefactorKit-owned repository identity/path, present descriptor hashes, selected-leaf proof, and exact sidecar-free no-follow absence without a provided-type claim or invented absent-content hash. A child below a pruned edge is not an offline leaf because it is not selected on that path.
|Build Model / Java move class
|Accepted ADR 0012; `RPK-JAVA-MOVE-002`; bounded implemented-and-validated `007` and `011`

|Ordinary Maven Repository Missing-binary Evidence
|RefactorKit-owned proof for one selected, fixed-release, non-reactor binary leaf in an explicitly configured simple local-only Maven-2-layout repository. Its complete effective descriptor closure is present and hash-bound, but its safely contained binary path is exactly absent before, staged, and under lock. Evidence binds coordinate/type/classifier/version, provider/layout/root, deterministic POM/JAR paths, affected closure source sets, selected-leaf proof, and no-follow absence fact hashes; it invents no absent-content hash and supplies no caller classpath or provided-type authority. Bounded REQ-JAVA-MAVEN-MOVE-AUTH-011 validates the unclassified `jar` form only, not a `test-jar` matrix.
|Java Maven move-class target-scoped authority
|Accepted ADR 0012; ordinary missing-binary concept reviewed 2026-07-30; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-011

|Reverse-observer Closure
|The target's owning source set plus every active Maven main/test source set whose effective dependency closure can legally resolve the target in the relevant image. The full reactor is needed to prove excluded siblings are unrelated; this closure is a structural input to the broader operation authority closure. Bounded `001` reports the owner separately and proves exactly three reverse observers. Bounded `002` proves their relation and binding-selected use forms: direct `catalog-pricing:main` (import, constructor, declared type), transitive `catalog-storefront:main` (import, `instanceof`, class literal), and test-only `catalog-acceptance:test` (Cucumber import, declared type, exact FQN), with no unrelated root added to any JDT source path.
|Build Model / Java move class
|`RPK-JAVA-MOVE-002`; `RPK-JAVA-DIAG-002..003`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-001/002

|Operation Authority Closure
|The union, across before and staged images, of the target owner, every reverse observer, and every source set whose JDT result contributes target-binding or retained-diagnostic evidence. Missing-binary coordinate/path and diagnostic non-concealment evidence is quantified over this closure, while structural graph and candidate-exclusion proof remains full-reactor.
|Java Maven move-class authority
|ADR 0012; `RPK-JAVA-MOVE-002..004`; bounded implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-001/002/009/010/011

|Managed-write Eligibility
|Explicit operation-scoped `ELIGIBLE` or `INELIGIBLE` decision evaluated under the workspace lock before WAL creation for otherwise eligible plans. For target-scoped Java move class it combines descriptor-closed selected-graph/prune evidence, global candidate exclusion, operation-closure missing-binary evidence where present, candidate-total exact bindings, retained-diagnostic non-concealment, exact staged no-new-error proof, freshness/conflict checks, and normal PatchEngine gates. Bounded `001` validates `ELIGIBLE` for two deterministic complete-`AVAILABLE` previews and revalidation through one exact staged-image transaction. Ordinary row `011` and negative rows `010`/`012` retain their separately bounded eligibility/refusal evidence. Preview, `OFFLINE_MISSING`, confidence, approval, caller classpath attestation, or Maven success is not eligibility.
|Core / Java / safety
|Accepted ADRs 0002, 0008, and 0012; `RPK-JAVA-MOVE-004`; bounded `001`/`002`/`007`/`009`/`010`/`011`/`012`

|Guided Manual Refactoring Fallback
|Distinct `REVIEW_ONLY_GUIDANCE` handoff for an intelligible request whose semantic authority is unavailable. It separates facts and candidate evidence, explains blockers and remediation, and gives a human/VCS-owned checklist. It is non-managed: no `PatchPlan`, applyable plan ID, WAL, transaction, or RefactorKit rollback claim.
|Java / integrations / user guidance
|`RPK-JAVA-MOVE-005/007`; field report `SRC-2026-07-29-004`

|Java Platform Signature Catalog
|Immutable, licensed, integrity-verified, hash-attested and SBOM-covered Java SE types, members, and release-appropriate module metadata used for exact `--release` diagnostics. It is distinct from source grammar, the host JDK, and RefactorKit's reduced jlink runtime.
|Java / packaging
|ADR 0012; `RPK-JAVA-DIAG-001`

|Maven Source-set Semantic Environment
|Complete hash-bound compile view for one active reactor module and one main or test source set: source/materialized-generated roots, outputs, Maven-scoped reactor/external visibility, Java settings/platform, provider evidence, and source-set availability.
|Build Model / Java
|ADR 0012; `RPK-JAVA-DIAG-002..004`

|Effective Maven Dependency Scope
|Scope derived with declaration provenance preserved. An explicitly declared transitive `test` scope remains `test`; a dependency-management scope default supplies scope only when the dependency declaration omits it. For an external transitive edge, a null or projection-excluded derived scope is a deterministic prune whose classification precedes child lookup when child facts cannot alter it.
|Build Model / Maven source sets
|Accepted ADR 0012; `RPK-JAVA-DIAG-002..003`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-009/010

|Reactor-root Workspace Authority
|Rule that the caller-declared full Maven reactor root defines both the readable workspace and effective-model boundary. Module targeting filters results after model construction and never authorizes implicit upward or outward discovery.
|Build Model / security
|ADR 0012; `RPK-JAVA-DIAG-002`

|Typed Unavailability
|A concise structured result stating that a semantic input or supported shape is unavailable for an affected source set. It replaces guessed diagnostics and is not equivalent to a source compiler error. It blocks global authority. For the sole target-scoped Maven `moveClass` mode, selected-binary `OFFLINE_MISSING` may proceed only after descriptor closure, candidate exclusion, and operation-closure evidence pass. Missing POM/parent/BOM/effective-model facts on an included edge always block; absence below a deterministically pruned edge is not a missing selected input. Outside-closure absence stays visible without being mislabeled operation evidence.
|Diagnostics / safety
|Accepted ADR 0012; `RPK-JAVA-DIAG-004..005`; `RPK-JAVA-MOVE-002..004`; implemented-and-validated `010`/`011`/`012`

|RiskLevel
|Risk classification for a patch or refactoring: LOW, MEDIUM, HIGH.
|Core / safety
|`Models.kt`

|Stable Contract
|An API `1.0` behavior or capability with a versioned schema/semantics, deterministic failure modes, compatibility policy, and passing RC acceptance evidence. Stability does not imply support for every refactoring shape.
|Release / integration
|`docs/releases/v1.0.0-plan.md`, ADRs 0002 and 0004

|Evidence Classification
|Per-operation outcome classified as JDT binding-backed, separately proven structural behavior, review-only lexical evidence, or refusal. In target-scoped move authority, lexical inventory is completeness/veto evidence only; it never upgrades a range to `JDT_BINDING` or mutation evidence. Exact JDT candidate counts stay separate from Java non-code and non-Java residual counts, both of which remain `managedEdit=false`. `LEXICAL_FALLBACK` must not be presented as semantic authority and is rejected before WAL; type-move authority loss yields non-managed guidance or refusal rather than an applyable fallback. Bounded `001` proves deterministic `JDT_BINDING` classification for one complete-`AVAILABLE` fixture request; bounded `002` proves exact binding versus residual discrimination for one observer-authority fixture request. A separate CLI/Linux/JDK-21 run at Magrathea commit `a48e3c06` remains a request-specific field qualification; none generalizes to other surfaces or native matrices.
|Java / safety
|ADRs 0002, 0008, and 0012; `RPK-JAVA-MOVE-003..005`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-001/002; dated Magrathea field evidence

|Release Candidate (RC)
|Immutable `v1.0.0-rc.N` tag used only after the deep language roadmap, Clojure integration, alpha/beta validation, and API freeze to validate proposed stable contracts and artifacts; a failed tagged candidate is replaced by a new commit and RC number.
|Release
