== Level 1: RefactorKit System

RefactorKit provides deterministic code-intelligence and refactoring capabilities with preview, validation, managed apply, and compensation semantics. Managed apply is a WAL-backed, recoverable, staged per-path transaction rather than one filesystem-wide ACID commit; admitted native LSP edits are version-checked and explicitly client-managed/no-rollback, and recipes reduce eligible staged steps to one managed transaction. Implemented REQ-JAVA-MAVEN-MOVE-AUTH-004 adds an operation-admission invariant for Java/Maven `moveClass`: legacy lexical fallback is an edit-free protocol review envelope, not a managed plan, client edit, or recipe aggregate. RefactorKit exposes capabilities through CLI, daemon, LSP, MCP, and library integration modes. For `v1.0.0`, the core patch, documented CLI, and documented daemon surfaces become stable API `1.0` contracts only after acceptance; LSP and MCP surfaces are stable only capability by capability where explicitly classified.

|Core Patch and Model Engine
|Kotlin/JVM library
|Workspace/project/source models, symbols, references, diagnostics, text/file/workspace edits, patch plans, preflight/sequential apply/compensation engine, post-apply transaction log, JSON-RPC primitives, and language adapter contract. Stable acceptance must freeze precise stale, overlap, path/symlink, same-file coordinates, bounds, filesystem capability, partial-failure, journal, isolation, apply, compensation, and recovery behavior. The managed-write boundary accepts only admitted `PatchPlan`s; Java-specific guidance and lexical review are not core patch inputs, pending plans, or transaction inputs. Generic immutable `OperationAuthorityFileEvidence` lets an adapter bind a safe workspace-relative non-managed file and typed attributes into an authority lease, while immutable sorted `DiagnosticDetails` carries structured refusal data. Under lock, `PatchEngine` captures one engine-owned observed snapshot and tracked-file hash map, compares expected/observed required-file-evidence identities, gives `authorityLease.evidenceDrift` precedence over secondary `snapshot.scopeChanged`, and refuses before WAL. Core does not claim an observed semantic candidate inventory. `RefactoringApplyIdentity.parse`, structured JSON-RPC data, and the lexical compatibility gate remain independent.
|`modules/refactorkit-core`, `Models.kt`, `PatchEngine.kt`, ADR 0002; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-003/004/008.
|implementation-informed for the bounded generic evidence values, one-observation under-lock refusal, identity parser, structured errors, and non-managed separation

|Internal Build Model SPI
|Language-neutral core contracts with ecosystem providers
|Internal `0.5.x` abstraction for module graphs, source sets, scoped dependencies, outputs, generated roots, typed model diagnostics, discovery policy, and hash-bound evidence. Core contracts plus explicit Maven-effective, Gradle-declarative, and conventional Java providers are implemented. The Gradle provider models a bounded literal main/test/integration/custom subset and returns `PARTIAL` or `EXECUTION_REFUSED` without invoking Gradle, scripts, tasks, plugins, or Tooling API. JDT environments and source ownership/planner consumers use provenance-preserving exact/longest-prefix Build Model queries with compatibility fallback. Providers never execute arbitrary build code silently or write the workspace.

|Java Language Adapter
|Kotlin/JVM library
|Java scan/symbol/reference/diagnostic/refactoring capability: offline plugin-free Maven effective-reactor modeling with separate main/test JDT environments and hash-bound parent/BOM/artifact evidence; lexical and JDT indexing of classes, interfaces, enums, records, and annotation types; JDT binding-backed class-style rename for types (including annotation types), signed method rename, and unambiguous `Owner#field` field rename; JDT binding-scoped move class; structural byte-identical whole-source-root relocation; per-file JDT binding-aware exact-import cleanup; JDT binding-backed safe delete; extract method MVP; change signature MVP; recipes; framework-aware risk detection; and explicit lexical fallback where defined. The semantic analyzer visits annotation-type declarations and records their binding identity, source ranges, nesting owner, and usage references. It visits annotation elements as zero-parameter signed `METHOD` symbols, records method-binding evidence, and excludes declaration names from reference results. Read-only lookup/reference queries and clean signed member rename therefore resolve exact annotation elements and binding-matched named usages. For a uniquely selected `FIELD` and clean global evidence, `JavaRenameMemberPlanner` uses exact field-binding declaration/reference ranges; owner-field collision validation occurs before semantic fallback. Unclean or unresolved evidence uses the explicit lexical member fallback, and arbitrary unsigned methods have no equivalent semantic guarantee. The analyzer also exposes import-context and non-import binding uses normalized to declaration bindings for generic type, method, and variable identities. Annotation-element change-signature and default-value editing are not implemented. For bounded Maven `moveClass`, Java owns the shared plan-free request preflight and the operation-specific three-arm outcome dispatcher. REQ-003 and four cases of REQ-008 use immutable schema/checklist-v1 `JavaMoveClassReviewOnlyGuidance`; the diagnostic-identity case is collected by the dispatcher's second stage. The fifth REQ-008 case remains on the `Plan(JavaMoveClassPreview)` arm and returns result-owned typed `JavaMoveClassStructuralRefusal` for a root-declared missing active POM. Eligible target-authority leases bind each non-managed `BOUND_OTHER` candidate source through generic core required-file evidence. REQ-004 independently owns immutable `JavaMoveClassLexicalFallbackReviewEnvelope`, its protocol projection, audit cache, and terminal recipe behavior. No REQ-008 case is lexical review; the four guidance results and structural refusal expose no managed plan/edit capability.
|`modules/refactorkit-java`, `JavaMoveClassOperationDispatcher.kt`, `JavaMoveClassGuidance*.kt`, `JavaMoveClassPlanner.kt`, `JavaMoveClassTargetAuthority.kt`, `MavenEffectiveReactorBuilder.kt`, `JavaProjectScanner.kt`, ADRs 0008 and 0012; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-003/004/008.
|implementation-informed baseline; bounded REQ-003/008 guidance and REQ-008 structural refusal are source-built library/CLI evidence, REQ-008 required-file lease revalidation is library/`PatchEngine` evidence, and the lexical envelope plus recipe stop belong to bounded REQ-004; authoritative general Maven diagnostics, packaged execution, runtime distributions, and native qualification remain product-critical gaps

== Key Dependencies

* CLI depends on core, Java and Kotlin adapters, daemon, web importer, tree-sitter foundation, and testkit.
* Daemon and MCP depend on core, Java, Kotlin, and shared JVM composition; LSP depends on core plus Java and Kotlin adapters.
* Shared JVM composition depends on core and both Java/Kotlin adapters.
* Java adapter, Kotlin adapter, web importer, tree-sitter foundation, and testkit depend on core.
* The planned authoritative Java diagnostics path makes the Java adapter consume the Java Platform Signature Catalog and the full declared Maven reactor/source-set Build Model before module-result filtering.
* Kotlin compiler classes are compile-only for the isolated bridge and are supplied explicitly only to the external worker; they are not loaded into the packaged RefactorKit process.
* Web importer reuses Java source-root/package/import knowledge.
