== Strategy Summary

RefactorKit is structured as a local, deterministic refactoring engine around a language-independent patch core and pluggable language/integration adapters. The primary strategy is to make changes previewable and diagnosable, with managed compensation after completely successful apply, for humans, CI, editors, and local AI agents. The audited current flows are preflighted compensatable batches, not ACID or crash-safe transactions; stronger rollback, isolation, durability, and recovery properties remain planned.

The release strategy published the hardened Java/transaction foundation as `v0.4.0`, the cross-platform runtime and multi-language kernel as `v0.5.0`, and the managed TypeScript/JavaScript semantic foundation as `v0.6.0`. Later `0.x` bands build deep adapters. API `1.0` freezes only after Clojure completes the planned language sequence and global alpha/beta/RC acceptance passes; active API remains `0.2` until an explicit migration. Stability is evidence-gated per language and operation; unsupported shapes remain conservative refusals.

|Incremental compiler-backed Java analysis with classified evidence
|Proven Java slices use exact Eclipse JDT binding evidence; prototype operations currently retain explicit lexical behavior or conservative refusal when semantic evidence is unavailable or not clean. Java annotation types are represented as first-class symbols by lexical and JDT indexing and reuse the existing type-level lookup, rename, move, safe-delete, recipe, and owner-validation paths. |Authoritative Java/Maven semantic environments
|For managed Java operations, RefactorKit—not Maven—is the definitive semantic diagnostics authority. |Target-scoped Maven move authority
|A qualified same-module/source-set Maven `moveClass` may use a narrower operation-specific authority mode without claiming global source-set completeness. Reactor graph authority is descriptor-closed per main/test projection: every active reactor POM is mandatory; every selected external node needs complete effective POM/parent/BOM/management/mediation/relocation closure; and each outgoing declaration has a hash-bound selected or exact scope/optional/exclusion-pruned result. A deterministically pruned external edge contributes no child node/subtree and triggers no child POM/JAR lookup on that path; another selected path restores those requirements. Selection precedes child version/repository/descriptor/binary lookup whenever downstream child facts cannot alter the result, while ambiguity and any missing descriptor on an included edge fail closed. Per-binary negative-presence and retained-diagnostic evidence is limited to the proven before/staged operation authority closure. Bounded `001`/`002` prove the complete-`AVAILABLE` and exact observer/candidate/residual strategies. Within an `OFFLINE_MISSING` closure, bounded `007`/`009`-`012` prove independently scoped missing-binary, scope, selector, ordinary-absence, and selected-descriptor behavior. Implemented-and-validated `008` closes six isolated evidence-phase failures: four complete preview uncertainties return immutable typed guidance; a root-declared missing active POM returns typed structural refusal; and an eligible `007` lease binds a non-managed `BOUND_OTHER` source as generic required-file evidence so one lock-held engine observation can return primary `authorityLease.evidenceDrift` plus secondary `snapshot.scopeChanged` before WAL. The semantic candidate-inventory hash is expected-only; expected and observed hashes describe required-file evidence, not an observed semantic candidate inventory. Caller-attested classpaths, Maven/plugin execution, settings credentials, implicit network, and lexical promotion remain forbidden.
|Accepted ADRs 0010 and 0012; `RPK-JAVA-MOVE-001..004` and `006..007`; `OperationAuthorityFileEvidence`, `DiagnosticDetails`, `JavaMoveClassStructuralRefusal`, `JavaMavenMoveClassAuthorityFailureCucumberTest`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-001 through `012`; dated Magrathea field evidence at `a48e3c06` remains separate.
|confirmed P0 architecture; all twelve bounded definitions and 22 expanded fixture cases implemented and validated; the exact Magrathea CLI request remains qualified only on Linux/JDK 21; generalization, broader integration shapes, packaged execution, runtime distributions, and native-matrix qualification remain open

|Java move-class plan/guidance handoff boundary
|The bounded Java adapter path uses a plan-free `JavaMoveClassRequestValidator` shared by `JavaMoveClassPlanner` and `JavaMoveClassOperationDispatcher`. The dispatcher is the direct Java move-class operation API and outcome boundary; it is not the generic `LanguageAdapter` `PatchPlan` API. Its disjoint outcomes are `Plan(JavaMoveClassPreview)`, `Guidance(JavaMoveClassReviewOnlyGuidance)`, and `LexicalReview(JavaMoveClassLexicalFallbackReviewEnvelope)`. `Plan` may carry managed, refused, or result-owned typed structural-refusal results and rejects lexical evidence. `Guidance` carries REQ-003 plus the four bounded preview uncertainties from `008`; the `008` diagnostic-identity case is collected in the dispatcher's second stage after a non-lexical preview. The `008` structural case stays on the `Plan` arm as `PatchStatus.REFUSED` with result-owned `JavaMoveClassStructuralRefusal` and no edit, lease, approval, or apply identity. `LexicalReview` carries REQ-004 alone and projects an internal compatibility preview as `LEXICAL_FALLBACK_REVIEW`. No `008` case returns `LexicalReview`, and only a fresh rescan/new preview can produce a separate managed plan.
|ADRs 0002, 0008, 0010, and 0012; `JavaMoveClassRequestValidator`, `JavaMoveClassOperationDispatcher`, `JavaMoveClassReviewOnlyGuidance`, `JavaMoveClassStructuralRefusal`, `JavaMoveClassLexicalFallbackReviewEnvelope`, and the JSON projections; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-003/004/008.
|implementation-informed for bounded REQ-003 source-built library/CLI outcomes, five REQ-008 source-built library/CLI preview-time outcomes, the REQ-008 library/`PatchEngine` under-lock row, and REQ-004's bounded direct-dispatch/CLI/recipe/daemon-session/LSP-session/MCP-session paths; no generic, packaged, runtime, or native qualification

|Legacy lexical-fallback protocol admission
|Every legacy Java/Maven `moveClass` `LEXICAL_FALLBACK` now leaves `JavaMoveClassOperationDispatcher` as immutable schema-v1 `LEXICAL_FALLBACK_REVIEW` before CLI/protocol rendering, pending-plan registration, recipe aggregation, or LSP edit conversion. Canonical JSON hashing produces request, exact snapshot, hidden review-artifact, and sorted-evidence SHA-256 identities plus deterministic non-capability `lexical-review-<sha256>` `operationId`. The hidden review-artifact identity commits to internal compatibility file-operation paths, exact edit ranges, and replacement/create bytes; exposed residual guidance contains only bounded path/content-hash/risk records with `managedEdit=false`, `COMPLETE or TRUNCATED` record completeness, deterministic returned-category counts, and fixed next actions. Protocols expose no plan/edit/range/replacement/apply token. Java-owned LRU audit caches retain immutable envelopes only, enforce 128-entry/16,777,216-byte limits, and clear on relevant session/workspace lifecycle changes. The shared exactly-one `operationId`/`planId` parser makes known operations typed `evidence.insufficient` refusals and unknown/evicted identities `INVALID_PARAMS`; daemon/LSP preserve structured JSON-RPC error `data`, MCP returns structured tool error content, and recipes stop without an aggregate. The core compatibility-plan gate remains defense in depth. This envelope remains disjoint from REQ-003 `REVIEW_ONLY_GUIDANCE`; clean JDT behavior remains the existing `Plan` outcome.
|ADRs 0002, 0004, 0008, and 0012; `JavaMoveClassLexicalFallbackReview*`, `RefactoringApplyIdentity`, CLI/recipe/daemon/LSP/MCP handlers, and `JavaMavenMoveClassLexicalFallbackReviewCucumberTest`; implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-004.

== Links to Decisions

Chapter 9 indexes the repository ADRs. ADRs 0002, 0004, 0005, 0006, and 0008 jointly record the stable safety, integration-boundary, packaging, least-privilege, and compiler-backed Java strategies. ADRs 0010 and 0011 define effective Build Model and non-executable/credential-free provider boundaries. ADR 0010 cross-references ADR 0012's narrow operation-specific refinement without changing offline, typed-root, plugin-free, credential-free, or network-default policy. Accepted ADR 0012 makes its full-reactor phrase precise: descriptor closure is over selected nodes and hash-bound edge classifications, stopping below a deterministic scope/optional/exclusion-pruned external edge on that path but resuming on any alternate selected path. Missing included descriptors still block. Subsequent bounded evidence does not change the ADR body: REQ-JAVA-MAVEN-MOVE-AUTH-001 validates a complete-`AVAILABLE`, binding-clean preview/apply/rollback row with two deterministic previews, exact staged diagnostics and post-image, one transaction, and exact rollback; `002` validates exact direct/transitive/test-only observer selection, JDT-only 12/1/0 target/other/unresolved candidate totals, separate non-managed one-Java-occurrence/two-non-Java-path residual reporting, unchanged exclusions, one exact apply, and exact rollback; `010` validates deterministic `PRUNED` records and lookup ordering plus alternate selected-path missing-POM refusal; `011` validates one fixed ordinary local-repository selected-`jar` leaf with sidecar-free absent-binary evidence and three under-lock drift refusals; and six-case `012` validates selected-descriptor structural refusals before semantic selection, lock, and WAL. Six-case `008` validates four non-lexical guidance outcomes, one result-owned active-POM structural refusal, and one under-lock required-file-evidence refusal with honest expected-only semantic inventory vocabulary. These implementation records update ADR 0012 evidence/mappings without changing its accepted decision. Separately, a source-built CLI qualified the exact Magrathea request at commit `a48e3c06` on Linux/JDK 21 after `010`, with `JDT_BINDING`, four affected files, one managed transaction, and exact source-tree hash restoration after rollback. That request-specific field result did not depend on `011` or `012`; none of the bounded fixture rows expands integration/native qualification or establishes general support.

The implemented lexical-review envelope and bounded REQ-008 refusal mechanics introduce no new person, external system, deployable container, durable store, or relationship. They are implementation consequences of ADR 0002's managed-plan/under-lock gate, ADR 0004's surface ownership, ADR 0008's evidence classification, and ADR 0012's fail-closed authority rules. The generic immutable required-file evidence and diagnostic-detail values remain core model data, not new runtime units. ADR 0012's evidence/mapping section is reconciled without changing its accepted decision; no C4 view change is required.
