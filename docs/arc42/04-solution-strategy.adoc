== Strategy Summary

RefactorKit is structured as a local, deterministic refactoring engine around a language-independent patch core and pluggable language/integration adapters. The primary strategy is to make changes previewable and diagnosable, with managed compensation after completely successful apply, for humans, CI, editors, and local AI agents. The audited current flows are preflighted compensatable batches, not ACID or crash-safe transactions; stronger rollback, isolation, durability, and recovery properties remain planned.

The release strategy published the hardened Java/transaction foundation as `v0.4.0`, the cross-platform runtime and multi-language kernel as `v0.5.0`, and the managed TypeScript/JavaScript semantic foundation as `v0.6.0`. Later `0.x` bands build deep adapters. API `1.0` freezes only after Clojure completes the planned language sequence and global alpha/beta/RC acceptance passes; active API remains `0.2` until an explicit migration. Stability is evidence-gated per language and operation; unsupported shapes remain conservative refusals.

The packaged-process qualification strategy for existing `REQ-JAVA-MAVEN-MOVE-AUTH-001` is now implemented as a deployment/test validation adapter, not product semantics: the authoritative feature/pickle is executed by a separate packaged Cucumber source set/task against the real unpacked self-contained CLI. Ordinary `test`/`check` remains source-built and packaging-independent. == Confirmed `v0.7.x` Completion Strategy

Status: confirmed program architecture, with implementation planned or otherwise open unless a separately cited bounded row is already qualified. The normative scope is link:../requirements/v0.7.x-completion-contract.md[`docs/requirements/v0.7.x-completion-contract.md`], and the requirements appendix owns the decomposed completion catalogue. Existing accepted decisions and historical execution evidence remain unchanged.

The completion strategy is *authority before aggregation*:

* Kotlin movement follows declaration ownership. A companion object cannot be selected as an independent move target; moving the enclosing type/file may carry it, while extraction is a different future operation. Standalone selection must fail with a stable typed refusal.
* TypeScript T5 is decomposed into source-file relocation, declaration move, module-specifier/project-reference migration, explicit organize-import modes, extract-function/constant, inline-variable, change-signature, and a separately proven inline-function row. The TypeScript adapter owns a typed anti-corruption layer over the pinned compiler/server protocol and returns immutable proposals or stable refusals. Dynamic/mixed JavaScript receives no inherited TypeScript authority.
* API `0.2` LSP module/identifier rename remains a client-managed proposal with no RefactorKit rollback. The separate managed retained-plan route is the only LSP route that may enter `PatchEngine` and claim WAL/recovery/rollback after its existing document guards.
* Recipes preserve the exact authority of every admitted child. A recipe cannot turn an operation-owned plan into a generic `recipe:<id>` plan with weaker evidence or diagnostics. Until a recipe-wide authoritative evaluator is proven, composition is limited to one authority-owning mutation plus non-mutating projection/summary steps.
* Release qualification joins operation evidence and native artifacts through one immutable release evidence identity and independently verifies the final published assets. A local run, source-built test, queued/running CI job, or intermediate artifact is not a release claim.
