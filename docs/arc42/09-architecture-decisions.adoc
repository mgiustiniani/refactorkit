== Decision Candidate Coverage

The ADR set covers patch safety, integration-surface and transaction-boundary classification, self-contained verifiable packaging, MCP least privilege, Eclipse JDT evidence-gated semantic authority, offline effective build models/source ownership, and the deferred supreme multi-language `1.0` target. ADRs 0003 and 0007 retain historical context but are superseded by ADR 0008. ADR 0009 supersedes the immediate post-`v0.3.0` Java-focused RC sequence without weakening any accepted safety decision. ADRs 0002 and 0004 record WAL-backed managed transaction guarantees, client-managed native LSP limitations, and the staged recipe-wide transaction boundary without claiming one filesystem-wide ACID commit. ADR 0010 separates package identity from module/source-set ownership, requires a shared Build Model SPI before deep JVM adapter expansion, and points to ADR 0012 for the qualified operation-specific use of `OFFLINE_MISSING` evidence. ADR 0012 keeps globally complete affected source sets as the stronger mode and permits the narrower target-scoped Maven `moveClass` proof only with global reactor/descriptor/candidate/platform/provider authority and closure-scoped missing-binary evidence. Implemented-and-validated REQ-JAVA-MAVEN-MOVE-AUTH-001/002 prove bounded semantic and observer/candidate/residual flows. Implemented-and-validated `003` proves four safely enumerable immutable Java guidance variants and the source-built CLI's pre-`PatchEngine` refusal; `004` proves the separate edit-free lexical-review outcome and bounded source-built/in-process surface path. Requirements `007`, `009`, `010`, `011`, and six-case `012` remain independently bounded. Implemented-and-validated six-case `008` is the phase-correct implementation of ADR 0012's existing fail-closed preview and under-lock freshness guardrails: four non-lexical guidance cases, one structural preview refusal, and one required-file-evidence refusal under lock before WAL. This is not a new decision. == REQ-004 Decision Fit

The implemented immutable schema-v1 `LEXICAL_FALLBACK_REVIEW` envelope does not change an accepted decision:

* ADR 0002 limits managed mutation to admitted `PatchPlan`/`PatchEngine` flows; an edit-free review envelope is not a planned change, while an internal compatibility `PatchPlan` remains rejected by the core evidence gate.
* ADR 0004 already separates CLI, daemon, LSP, MCP, recipe, managed-write, and client-managed ownership boundaries. The envelope prevents an ineligible result from crossing either write boundary and permits only an optional bounded edit-free audit cache, not new durable state.
* ADR 0008 requires explicit lexical classification and forbids lexical evidence from masquerading as semantic authority.
* ADR 0012 explicitly forbids approval, force, recipe composition, or protocol translation from promoting `LEXICAL_FALLBACK`.

Therefore no ADR body or C4 model change is required by this bounded implementation. The envelope and in-memory bounded audit cache add no person, external system, deployable container, durable store, or relationship. A later ADR is required only if future work proposes different mutation authority, a durable review store, or a new protocol/state ownership boundary.
