## Findings

### HIGH — File-local helper callable references still bypass the claimed fail-closed refusal

**Why this blocks promotion**

The sealed requirement and candidate docs say callable references are out of scope and that compiler PSI now causes pre-plan refusal:

- Requirement excludes callable references and requires exact retained outbound bindings:
  - `docs/requirements/kotlin-jvm-move-top-level-function-and-companion-refusal.md:15`
  - `docs/requirements/kotlin-jvm-move-top-level-function-and-companion-refusal.md:30`
- Candidate docs claim file-local source callable references are refused before planning:
  - `docs/kotlin-adapter.md:232-241`
  - `docs/releases/v0.7.0-k5-move-next-acceptance.md:123-126`

**What the implementation actually does**

- The planner checks `containsCallableReference` only on the **selected public function**:
  - `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:87-99`
- The same planner explicitly allows private top-level helpers in the moved file:
  - `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:125-129`
  - `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:170-172`
  - `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:756-769`
- Compiler PSI records callable-reference presence per function, but the planner never aggregates helper declarations’ flags:
  - `modules/refactorkit-kotlin/src/main/java/org/refactorkit/kotlin/bridge/KotlinCompilerSymbolExtractor.java:231-236`
- Private top-level properties are also admitted as helpers, and their evidence hard-codes `containsCallableReference=false`:
  - `modules/refactorkit-kotlin/src/main/java/org/refactorkit/kotlin/bridge/KotlinCompilerSymbolExtractor.java:411-415`
- Outbound equivalence compares only recorded usages / external usages, so any unrecorded helper callable-reference binding is invisible:
  - `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:242-250`
  - `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:344-353`
  - `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:693-716`

**Executable counterexample**

Using the source-built CLI from this candidate (`modules/refactorkit-cli/build/install/refactorkit/bin/refactorkit`) under JDK 21, I created a temporary workspace from `samples/kotlin-maven-simple` with:

```kotlin
package fixture.api
private fun helper(): () -> String = ::dependency
fun publicGreeting(): String = helper()()
```

plus:

- `fixture.api.dependency(): String = "source"`
- `fixture.api.v2.dependency(): String = "target"`
- one explicit Kotlin import consumer of `publicGreeting`

Observed results:

1. `refactorkit kotlin move-declaration ... --symbol <publicGreeting> --to-package fixture.api.v2 --accept-external-consumer-risk`
   returned **`"status": "PREVIEW"`** with **`"diagnosticsAfterPreview": []`**.
2. The same command with `--apply` returned **`"status": "applied"`** with **`"diagnostics": []`**.
3. `refactorkit kotlin definition` at the callable-reference site returned `kotlin.usageNotFound` both before and after apply, confirming that binding site is still absent from the evidence model.

This is a clean semantic rebound: the file package changes, the `::dependency` text is untouched, and Kotlin will now resolve that unqualified callable reference against same-package `fixture.api.v2.dependency` instead of `fixture.api.dependency`, with no compiler error. That is exactly the class of behavior-changing, compile-clean rebound the row claims to fail closed against.

**Required correction**

Before promotion, the planner must refuse callable references anywhere in the moved file’s permitted helper set, not only on the selected declaration. At minimum:

- aggregate `containsCallableReference` across all moved-file declarations admitted by `supportedFileDeclarations`, or
- add a whole-file PSI proof for callable-reference absence and fail closed on any positive hit.

A new immutable revision, updated focused oracle, and fresh four-host rerun are required.
