## 3. Findings

### HIGH — Outbound source callable references can silently rebind after the move

The requirement demands exact retention of every compiler-proven outbound source callable binding and leaves callable references unqualified:

- `docs/requirements/kotlin-jvm-move-top-level-function-and-companion-refusal.md:15`
- `docs/requirements/kotlin-jvm-move-top-level-function-and-companion-refusal.md:30`

However, the compiler usage extractor deliberately discards source-backed callable references:

- `modules/refactorkit-kotlin/src/main/java/org/refactorkit/kotlin/bridge/KotlinCompilerUsageExtractor.java:289-291`

An existing test confirms this behavior: `::target` is intentionally absent from resolved usages:

- `modules/refactorkit-kotlin/src/test/kotlin/org/refactorkit/kotlin/KotlinCompilerDiagnosticsTest.kt:689-706`

The move planner’s outbound comparison only examines the resulting internal/external usage collections:

- `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:238-247`
- `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:340-349`
- `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:689-712`

Consequently, this cleanly compiling shape is not fail-closed:

```kotlin
// source package, moved file
fun moving(): () -> String = ::dependency
```

If the source and destination packages each contain a compatible `dependency`, moving the file changes `::dependency` from the source declaration to the destination declaration. Compilation remains clean, the selected function’s descriptor remains unchanged, and the omitted callable-reference binding does not appear in either outbound map. The planner can therefore preview and apply a behavior-changing semantic rebound.

The focused tests cover callable references only as consumers of the selected function:

- `modules/refactorkit-jvm/src/test/kotlin/org/refactorkit/jvm/KotlinJavaPublicTypeRenamePlannerTest.kt:684-700`

They do not cover callable references inside the moved file, so all four native receipts can pass despite this gap.

This must be corrected by either:

1. projecting source callable references with exact callable identities into outbound evidence; or
2. refusing any callable-reference form in the moved file using exact PSI evidence.

A regression must enter the sealed focused oracle, followed by four-platform rerun on a new immutable revision.

The native evidence is internally consistent and correctly bound, and the unrelated whole-CI failures do not defeat the dedicated gate. Nevertheless, the outbound callable-reference omission violates the required semantic-closure and fail-closed behavior. No listed roadmap row is authorized for closure.
