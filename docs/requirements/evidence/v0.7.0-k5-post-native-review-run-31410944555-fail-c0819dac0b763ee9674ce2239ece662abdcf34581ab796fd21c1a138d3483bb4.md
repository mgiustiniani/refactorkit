## Findings

### HIGH — Compiler-desugared `for`-loop callable bindings are omitted and can silently rebind

The sealed requirement demands retention of every outbound callable binding:

- `docs/requirements/kotlin-jvm-move-top-level-function-and-companion-refusal.md:15`

The compiler usage visitor handles explicit resolved names, calls, type references, qualifiers, and imports:

- `modules/refactorkit-kotlin/src/main/java/org/refactorkit/kotlin/bridge/KotlinCompilerUsageExtractor.java:181-210`

For source callables, however, it records a usage only when the attached PSI token text equals the resolved callable name:

- `KotlinCompilerUsageExtractor.java:271-282`
- `KotlinCompilerUsageExtractor.java:383-399`

A Kotlin `for (value in box)` is compiler-desugared through `box.iterator()`. Its implicit `iterator` resolution has no literal `iterator` token; the available PSI source is the range expression/token such as `box`. It is therefore absent from the emitted usage evidence. The planner then compares only the emitted internal/external usage lists:

- `modules/refactorkit-jvm/src/main/kotlin/org/refactorkit/jvm/KotlinJvmMoveDeclarationPlanner.kt:248-257`
- `KotlinJvmMoveDeclarationPlanner.kt:350-360`
- `KotlinJvmMoveDeclarationPlanner.kt:699-722`

The new callable-reference facts do not help because they recognize explicit `KtCallableReferenceExpression` syntax, not implicit convention calls:

- `KotlinCompilerSymbolExtractor.java:252-254`
- `KotlinJvmMoveDeclarationPlanner.kt:125-135`

#### Executable counterexample

I built and executed this temporary clean workspace against the source-built packaged candidate:

```kotlin
// neutral/Box.kt
package neutral
class Box(val values: List<String>)

// fixture/api/Iterator.kt
package fixture.api
import neutral.Box
operator fun Box.iterator(): Iterator<String> = values.iterator()

// fixture/api/v2/Iterator.kt
package fixture.api.v2
import neutral.Box
operator fun Box.iterator(): Iterator<String> = values.asReversed().iterator()

// fixture/api/PublicGreeting.kt — moved file
package fixture.api
import neutral.Box
fun publicGreeting(box: Box): String {
    var text = ""
    for (value in box) text += value
    return text
}

// fixture/consumer/Use.kt
package fixture.consumer
import fixture.api.publicGreeting
import neutral.Box
fun use(): String = publicGreeting(Box(listOf("a", "b")))
fun main() { print(use()) }
```

This satisfies the bounded source-file and consumer shapes: one plain public function, no helper declarations, one exact unaliased Kotlin import, no Java consumer, and explicit external-risk acceptance.

Observed:

1. K2 compilation before the move: success.
2. Runtime before the move: `ab`.
3. Move preview to `fixture.api.v2`: `PREVIEW`, no refusal, `diagnosticsAfterPreview: []`.
4. Apply: `applied`, diagnostics `[]`, with a transaction ID.
5. K2 compilation after apply: success.
6. Runtime after apply: `ba`.

The unchanged `for` expression silently rebinds from `fixture.api.iterator` to `fixture.api.v2.iterator`. This is a cleanly compiling behavior change and directly violates the exact outbound-binding requirement. Staged K2/JDT diagnostics cannot detect it because both programs are type-correct.

The implementation must either project exact FIR identities for all implicit convention calls—at least iteration, destructuring, containment, indexing, and delegation—or refuse any moved declaration containing an implicit call whose exact binding is not represented. A regression must enter the sealed oracle, followed by a new immutable candidate and four-host rerun.
